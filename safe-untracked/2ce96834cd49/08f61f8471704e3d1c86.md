## Review findings

### Blocker 1 — immutable tag race

The workflow has no publication concurrency group. It checks tag absence only once
before the potentially slow build, then later runs `imagetools create --tag` without
another absence check. Concurrent dispatches or an intervening tag creator can both
pass preflight and the later command can replace the supposedly immutable tag.

Required repair: serialize this image/version publication, repeat fail-closed tag
absence immediately before tag creation, and retain post-creation plus post-
attestation tag-to-digest equality checks. Add structural concurrency/race tests.

### Blocker 2 — SBOM attestation is claimed but not verified

The workflow runs one generic `gh attestation verify`. Current `gh` semantics default
that command to predicate `https://slsa.dev/provenance/v1`; it therefore verifies
provenance only. It does not verify the SPDX/SBOM attestation, yet the release receipt
sets `sbom_attestation_verified:true` and `spdx_sbom_verified:true`.

Required repair: run and preserve separate exact verification for SLSA provenance
and the SPDX predicate type, bound to exact digest, repository, workflow, source
digest/ref and hosted-runner policy. Preserve JSON verification artifacts and their
hashes in the receipt/packet. Tests must assert two predicate-specific checks and
that receipt/upload occurs only afterward.
