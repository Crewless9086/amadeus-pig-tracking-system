# Green 0.3.1 transport unblock plan

Business result: **NO BUSINESS OUTCOME**. Green remains stopped and
uncommissioned.

## Read-only findings

1. The current authoritative application is hosted on Render and the repository
   exposes no implemented private-LAN canonical HTTPS origin, private reverse
   proxy, private DNS registration or private CA issuance path for the Documents
   claim service.
2. Green 0.3.1 requires a private-only canonical hostname, a pinned private IP
   in that hostname's DNS answer set and `/config/private-ca.crt`. Those required
   Home Assistant options are empty. The required private canonical transport
   therefore does not presently exist as a commissionable system.
3. The fixed queue initializer requires an `ipps://` URI containing a private IP
   literal. The printer certificate must contain that IP identity. No governed
   printer URI, certificate identity or queue registry entry is configured, and
   no existing private IPPS identity could be proven from the available router or
   Home Assistant surfaces without exposing private values.
4. No credential, registry identity, DNS, proxy, CA, queue or configuration was
   created. Green remained stopped with boot, watchdog and auto-update OFF.

## Smallest safe correction

Prepare Green 0.3.2 with two explicit outbound-only transport profiles:

- `canonical_transport=public_pki_exact_origin`: allow only the exact configured
  HTTPS Render origin, use normal public-PKI hostname verification, forbid
  redirects and origin/path changes, retain least-privilege bearer plus farm and
  Green identity binding, and remove the unstable public-IP pin requirement.
  Green exposes no inbound route, so this does not publish Green or the printer.
- `printer_transport=private_ipps`: keep IPPS mandatory, but allow either a private
  IP literal whose certificate contains that IP or a commissioned printer hostname
  whose certificate contains that hostname and whose entire DNS answer set is
  private. Bind the resolved address set at initialization and fail closed on
  public, changed or ambiguous resolution. Never fall back to plain IPP.

Do not weaken TLS, use a public printer route or introduce an ad-hoc canonical
proxy merely to satisfy the old private-origin assumption. If the printer exposes
no verifiable IPPS certificate under either identity form, the next action is a
separate printer-side certificate/IPPS commissioning by an authorized local
operator; Green must remain stopped.

## Three-day execution path

1. Implement the two typed profiles, validation, redirect prohibition and
   private-hostname IPPS resolution binding with negative tests.
2. Independently review and release 0.3.2 at an immutable digest.
3. A secure local operator verifies the printer IPPS identity without disclosing
   it, registers the exact Green/printer/queue identities, provisions one
   least-privilege canonical token through the protected options UI, and performs
   the already-authorized zero-job start/health/empty-queue/stop proof.
4. Only after zero-job commissioning passes may Control Tower request the separate
   genuine one-page physical acceptance authority.

Owner action: **NONE** until the reviewed 0.3.2 candidate and secure local operator
are ready.
