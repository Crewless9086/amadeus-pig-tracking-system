# Unstarted auxiliary reconciliation

The root operator may reconcile one exact `restart_or_deadline_ambiguous` auxiliary claim only after current authoritative exact-device OFF and canonical history prove no dispatch marker, ON outcome, Active row or completion ever existed. `reconcile_unstarted_auxiliary` requires the original claim and containment event IDs and SHA256 digests, genuine owner instruction/reference and root review digest. It locks the normal execution/auxiliary rails, rejects another open auxiliary owner, and appends one idempotent reconciliation event. Only that referenced containment is superseded; old claims, OFF outcomes, containment and daily reserved seconds remain. A new operation must pass all normal batch, energy, configuration, budget and ownership checks. No ON, automatic retry, time refund, completion or premix credit is granted. Private commissioning must finish expensive evidence reads before setting the claim clock, use that still-fresh evidence at the locked ON edge, and stop if the unchanged 25/30-second startup bounds expire.

The managed borehole start records the exact assessed eligibility before claiming. The native check consumes the transport's normalized `native_inching_enabled` and `native_inching_seconds` fields. After the native-safety read, the coordinator takes a fresh claim clock and derives both stop deadlines from it; assessed evidence and provenance are unchanged. Persistence failure, unsafe native configuration, active-only supervision and the existing 30-second locked dispatch fence still prevent a new ON. Tests with historical scheduler times must inject the coordinator clock explicitly; production uses the current wall clock.
