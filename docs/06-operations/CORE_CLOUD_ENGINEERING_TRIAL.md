# Bounded cloud engineering qualification

Lifecycle: evidence and operating guide; not doctrine.

The existing Render CORE worker has an opt-in engineering mode in addition
to the unchanged receipt-only and legacy commissioning modes. It does not
automatically turn received manager findings into coding authority.

One fresh, paused canonical mission receives an explicit owner-admin grant.
The grant binds the current owner, latest owner correction, exact deployed
web/worker/base revision, source paths, immutable acceptance test, time limit,
and maximum model spend. The existing mission and append-only event rails
retain claim, stage, reservation, completion and revocation evidence. No
parallel mission queue is introduced.

The worker claims exactly that mission once, authors a structured patch through
the existing Hermes model boundary, applies only the authorized files, and
runs fixed tests in a Linux sandbox. It must first reproduce the independent
failure on the original source. Fresh security and functional reviewers receive
the actual diff, source and test evidence. The output is a private candidate
artifact; publication, protected merge and deployment are separate release
actions. A private artifact is not a deployed farm outcome.

The competing-writer check projects compact grant state and filters active
cloud candidates before checking their revocation history. It still checks
legacy and native leases on the current mission and other missions, and keeps
the existing database deadline and statement/lock limits. No cached authority
or new database schema is introduced.

The worker stops on unknown outcomes, changed owner instructions, holds,
expiry, conflicting writers or exhausted budget. Verified test failures and
concrete reviewer findings can return to the builder for a bounded correction;
all attempts share the same deadline and eight-call spending limit.
A provider restart never reuses a consumed claim. An issued grant is not renewed
automatically. Revocation is append-only so a hold cannot prevent recording it.

## Spending and isolation

Strict model mode uses the configured OpenRouter GPT-5-mini route with explicit
price ceilings, no tools, one physical request, and no hidden retry or fallback.
Each attempt reserves USD0.10 before contacting the provider. At most eight
attempts reserve USD0.80 for one grant; uncertain calls remain charged against
that bound. This is a trial allowance, not a claim about the account's total
daily spending or another application's budget.

The test launcher requires root-controlled Linux staging, drops to a dedicated
unprivileged UID, uses Landlock and seccomp, denies network/process creation,
and limits memory, time, files and output. It cannot access production
credentials or write the candidate. Unsupported hosts fail closed. Its
trusted acceptance test is injected outside the agent's editable paths.

No new Render service or instance size is required. Enabling this mode replaces
the existing worker mode; receipt-only commissioning must be inactive first.
Windows CORE remains stopped.

## Acceptance still required

Source tests and CI do not prove the cloud outcome. Acceptance requires the
exact worker deployment, natural pickup, cloud-authored candidate, original
failing and corrected passing regression evidence, independent review of that
candidate, canonical artifact readback, a later idle cycle with no duplicate
model call, and revocation. The selected first repair concerns order-dependent
duplicate mortality evidence; it must use synthetic records and does not close
unresolved historical mortality lineage or establish physical farm facts.

The current implementation is under qualification. No engineering trial has
yet run and no autonomous coding outcome is claimed.
